# Shared contracts, version 1.0.0

The normative shapes are [v1.schema.json](contracts/v1.schema.json). API wire names are snake_case. Generate or write Go/TypeScript bindings from these definitions once; runtime validation and examples must enforce the same constraints. This is a deliberate replacement of the legacy full-state WebSocket shape. Keep legacy .f1bin import, not a second live API.

## Identity, clocks, and measurements

Opaque local IDs are UUIDs in production; compact IDs in fixtures are valid examples. Decimal strings carry uint64 game UIDs and observation/frame sequence numbers to avoid JavaScript precision loss. Epoch times are integer milliseconds; MCAP raw timestamps retain nanoseconds. Session time is a separate rewindable game clock. Raw zero game/link IDs decode to null; non-null game/link IDs are nonzero decimal strings, never a global join key.

Context distinguishes source_context_id, session_id (logical saved session), fragment_id (one received connection/UID fragment), branch_id (one attempt), and game_session_uid. source_context_id is a persisted local UUID assigned automatically per recorder installation and remote sender IP, ignoring ephemeral sender port; this adds no pairing/setup step. Imports get a fresh source context unless an MCAP manifest proves its existing identity or the user explicitly assigns it. A changed sender address remains unassigned until linked. One address can conceal distinct saves/installs, so conflicting evidence remains ambiguous and requires manual grouping.

receive_seq is allocated strictly increasingly per persisted source_context_id, including duplicates/invalid datagrams and continuing across sessions/branches/fragments. This avoids renumbering pre-session fragments or resumed sessions. Reserve sequence blocks of4096 durably in the source-context catalog before use; after restart skip unused reserved values rather than reuse them. These holes do not imply dropped datagrams. observation_seq is the highest receive_seq incorporated in the immutable snapshot; derived events cite it. Sequence holes after live rejection are normal. ExportRow.seq is original receive_seq; replay preserves it. Range endpoints are inclusive receive-sequence bounds; evidence is strictly after the last accepted cursor through the frozen upper bound. Analysis Query time ranges separately use half-open milliseconds. Stream sequences never replace evidence sequences. Source selection is live:<session_id> or replay:<replay_id>; session histories have no effect on live selection. Revision increments on changed context, not every packet.

Measurement available requires a finite non-null typed value and source_id. Every other availability requires null, including stale; as_of_ms may retain the last observation timestamp. Never publish NaN, infinity, sentinel 255, or restricted zeros as a value. Unit strings come from the channel catalog. Confidence describes evidence, not a probability invented by a model. Raw datagrams remain unchanged for future reprocessing.

Canonical channels use dotted names: car.speed_mps, car.throttle_fraction, car.brake_fraction, car.gear, car.rpm; tyre.fl.surface_c/core_c/wear_pct/pressure_pa and corresponding fr/rl/rr; energy.store_j, energy.deploy_mode, energy.harvest_limit_j_per_lap; fuel.mass_kg, fuel.finish_margin_laps; timing.lap_ms, timing.speed_trap_mps; aero.active_mode, overtake.eligible, boost.active. Publish official raw field mappings and all additional decoded channels in GET /channels. Wheel arrays are RL, RR, FL, FR in UDP and map explicitly to presentation positions. Convert UDP km/h to m/s, PSI to Pa (6894.757293168), and watts to kW only for display. Wear percent means consumed life; remaining life is 100 minus wear with a distinct label.

Freshness uses receive monotonic time for live expiry. High-rate channels expire after 1000 ms, status/damage after 3000 ms; event/single-session/history data persists with its as-of and source until replaced/session changes. A disconnected stream is stale after 2000 ms. Replay pauses freeze the playhead and show Paused instead of expiring against wall time. Invalid measurements do not clear a valid alert.

## HTTP surface

Context.formula_code and raw game_major_version/game_minor_version preserve header/session evidence directly. Match formula-scoped profiles on formula_code, not by parsing season_evidence strings. These software version bytes are not proof of a named game patch/build; leave a setup source build comparison unknown when no reliable patch identity is available.

For each car retain packet16 m_2026Regulations as regulation.applies_2026 (available boolean) where broadcast. Player-car flag true identifies2026 regulations; false identifies pre2026 only, with supported formula/car context required before labeling it2025. Formula13 is explicit2026 evidence when the per-car flag is absent. A false flag conflicting with formula13, or inconsistent active player context, yields unknown with both sources retained. Never infer2026 from packetFormat alone.

All routes below are relative to /api/v1; JSON errors use {code,message,request_id,details}. Expected statuses: 400 malformed input, 404 missing ID, 409 incompatible state/revision, 413 limit, 422 unsupported semantic configuration, 503 unavailable subsystem. Empty success is not an error fallback. No route validates Origin or requires an application credential. GET /config redacts provider keys and returns configured booleans; PATCH accepts secret values but never echoes them.

The [operation catalog](contracts/http-operations.json) maps every method/path to exact request/response definitions. Lists use items and nullable next_cursor; limit defaults25, maximum100. Success is200, creation201 (careers/replays/setups/experiments), queued work202 (imports/exports/engineer requests), and DELETE returns200 with its stated body. Errors use Error. /stream uses StreamSubscription and StreamMessage. Add POST /setups/{id}/experiments with ExperimentCreate -> Experiment for outcomes.

Query, CompareQuery, AnalysisResult, LapSummary, StrategyQuery, StrategyEvaluation, StrategyCandidate, ExportRequest, Job and Request define analysis/model payloads. StrategyCandidate includes nullable projected race time, pit loss, rejoin position, error band, legality and assumptions; do not reduce it to prose in an Estimate. Tool data for read_telemetry_window is ReadWindowResult (bounded series plus events), compare_laps is AnalysisResult, evaluate_strategy is StrategyEvaluation, search_setups is SearchResult and fetch_setup_source is SourceInspection. ToolResult.data must validate against its corresponding definition; errors use null data. Series have stable artifact IDs.

ReferenceProfile, CapacityProfile and TrackProfile are editable Config fields with source/applicability/calibration metadata. Empty applicability arrays mean all known values in that dimension, never inferred values for unknown context. A profile with explicit season/formula constraints does not match unknown/conflicting context. Seed only the provisional profiles in defaults.json; cold/core/2026 temperature ranges remain unset until sourced. Native Settings and browser Settings use the same config contract.

ConfigPatch carries the complete desired Config plus secret updates {id,value} and delete_secret_ids. Secret IDs are referenced by api_key_env fields: resolve an actual process environment value first, otherwise the same ID in the local secrets store. A missing/null reference means no key. Read APIs expose only secrets_configured booleans. Redacted active_config and desired_config remain separately visible when a bind change requires restart. If-Match is the decimal revision in quotes; a missing precondition returns428, and a stale revision returns409 without changing config.

Analysis uses half-open [from,to) intervals on a named branch. Responses report actual returned coverage. Indexed raw scans are cancellable by request context and limited to 30 seconds; timeout returns a structured error with a narrower-range suggestion. Limit work concurrency to two analysis/export jobs; one import job; ingestion and recording have independent reserved execution. UI shows queued work and permits cancellation.

## Streaming

GET /stream upgrades to WebSocket. Client sends StreamSubscription. Server sends an initial snapshot and incremental StreamMessage entries at the requested max_hz (default 20, cap60 for selected-car telemetry). Standings/status default5Hz; events/status send immediately. A metric delta replaces the whole wrapper by stable metric ID; omitted metrics remain unchanged; removed_metric_ids deletes explicitly. Snapshot resets that source. base_seq must equal the last applied stream seq. Stream seq is per connection/source and distinct from observation_seq inside model observations.

Use a bounded 256-message/4MiB send queue per client. Coalesce pending telemetry deltas; never let a slow client block ingest. If continuity cannot be preserved send resync_required, then a fresh snapshot. On reconnect request a fresh snapshot; do not infer replay from old client sequence. A new subscription replaces the old one on the same socket. Maximum incoming message64KiB. StreamMessage engineer_outputs, alerts and jobs carry accepted outputs, condition states and job changes on this connection; absent updates are empty arrays. No Origin check, auth handshake or pairing message exists.

## Scheduler and acceptance

TriggerRule predicates are typed, maximum nesting4 and total64 nodes. Evaluate on completed laps, event arrival, manual input, and a software timer only if a time/continuous rule is enabled. Lap counts refer to surviving completed laps after the scheduling cursor; replay/seek and flashback duplicates do not increment them. ALL latches its leaves since the previous dispatch of that rule; ANY fires when one leaf is satisfied. Time uses monotonic time, pauses while the game is paused, and does not backfill a burst after downtime. Rule filters apply before latching. car_scope player includes session-wide events; relevant rival events are emitted with the player as affected scope and rival evidence attached.

Coalesce routine events for1000ms. Manual/critical triggers bypass only coalescing; rule cooldown, minimum dispatch gap, concurrency and budgets still apply to AI. All applicable limits must pass, so effective dispatch time is the latest required deadline. The30-second notification gap does not delay model dispatch. A manual question preempts a scheduled run; branch/session changes cancel it. Routine events merge into pending evidence. Critical deterministic alerts still display when AI is delayed/budget-blocked. Evidence remains pending.

max_calls_per_hour counts provider HTTP requests, including tool-loop and repair requests, not logical invocations. max_tokens_per_hour counts input+output, including cached/reasoning tokens in provider total usage; reserve estimated input plus maximum output and reconcile actual usage. Unknown usage consumes the reservation. Use rolling60-minute counters across manual/continuous/analysis/research. Defaults are60provider requests and120000total tokens/hour. Four steps includes any repair. Dollar ceilings require configured prices. Continuous mode visibly pauses at the first exhausted limit and can resume at reset only within the original15-minute enable period; expiry disables it until re-enabled. The10-second cadence is an upper request cadence, not a guaranteed budget allowance.

Scheduling cursor is a dispatch checkpoint (rule/lap/time latches). Evidence cursor is the last observation successfully represented by an accepted strategy. On timeout/cancellation/invalid/superseded output update last_attempt and scheduling cursor but leave evidence cursor unchanged. On accepted scheduled/continuous strategy atomically persist output + its observed upper bound + evidence cursor. Live questions/post-race/setup results do not advance the live strategy evidence cursor. New events arriving during execution remain for the next window.

A branch change records last_inherited_seq strictly below the anchor, resets new-branch evidence_cursor/previous_accepted to null, resets all lap/time/rule scheduling latches and clears opaque provider state. Re-evaluate the surviving inherited prefix plus child evidence using bounded summaries; do not claim the anchor or abandoned future was accepted. The first lap trigger counts only newly completed child laps. A new logical session also starts with null accepted output/cursors and a new conversation. A positively linked new-UID fragment of the same logical session can retain that session's history after context validation. Provider/model/protocol/endpoint changes clear opaque state and start a new conversation with portable accepted advice. A continuation-specific expired/invalid rejection similarly clears opaque state for the next software invocation, records its reset reason and never retries within the failed invocation.

Each AgentInput contains the previous accepted AgentOutput, returned rationale summary if available, last attempt, outcomes, and bounded unaccepted events/changes. Include current selected-car state, nearby rivals, deterministic estimates and last5 clean laps. Bound metrics to512, individual recent events to64 plus up to64 additional critical events. Beyond that include deterministic counts/type/severity/time summaries and coverage.truncated/omitted_event_count. Summaries retain safety/weather/flag transitions and data gaps. Never imply omitted evidence was inspected. Context budget includes prompts/tool schemas/provider state; trim optional detail first, keep previous accepted plan and outstanding critical summaries. If minimum input cannot fit, fail the invocation without consuming evidence.

AgentOutput must match invocation/session/branch/observation scope and JSON schema. Evidence IDs must exist in supplied input/tool outputs. Numeric strategy claims must match deterministic estimates or be labeled assumptions. Accept only a complete terminal JSON object, never partial streaming text. Allow one schema-repair request within the same deadline/budget; otherwise mark invalid. No automatic provider/network retry inside a live invocation. A provider error waits for the next software trigger/manual retry. Runtime notification policy has final authority over notify and urgency; critical requires matching deterministic critical evidence.

Default timeout15s for live,90s for analysis/research. Max4 model steps,8 tool calls,2048 output tokens,16384 context tokens (clamped to endpoint context). Continuous mode default disabled; enabled session lasts15 minutes with10-second cadence and visible pause/stop/cost counters, then stops until re-enabled. One logical conversation may require several provider requests; it never creates an unlimited polling loop.

## Provider and tool contracts

Observation.strategy_evaluation carries frozen structured candidates when available; null means no evaluated candidates. A pit/energy/fuel strategy plan cites candidate_id and matching evidence, and pit windows/compound must agree with that candidate. hold/review/setup_experiment use candidate_id=null unless explicitly tied to a candidate. retire requires direct deterministic retirement/failure evidence; a thermal reference alone cannot authorize it. Preserve full candidate structures through tools/HTTP instead of encoding lap/compound in an estimate ID.

Chat adapter preserves assistant tool_calls with original IDs, parses JSON arguments, executes each registered tool exactly once per invocation/call ID, and returns role=tool/tool_call_id messages. Responses adapter preserves function_call/call_id plus required opaque reasoning/continuation items and returns function_call_output. Finish streaming before persisting continuation. Opaque state stays server-side in its original provider scope; it is excluded from model-visible rationale and standard exports. No demand for hidden chain-of-thought. A reasoning/rationale summary is optional and absence never blocks a strategy call.

Tool names and exact inputs are in prompts/v1/tools.json. Each result uses ToolResult with success/warning/error, one-line summary, next_actions, artifacts and structured data. Error includes cause_hint, retry instruction and stop_condition. Tools are reads/calculations only. Tool observation/strategy payloads reuse these definitions. Models cannot change trigger rules, telemetry, config, setup values, recordings, or notification policy. Web search is registered only for setup_research and an explicit post-race setup request.

## Exports

Download ZIP contains exactly one requested data.<format> file plus manifest.json (ExportManifest). ExportRequest/ExportManifest ranges are inclusive original receive-sequence bounds; ExportRow.seq is receive_seq. UI time selections resolve to those bounds and show actual coverage. All formats use the same long-form ExportRow columns. Exactly one typed value column is populated for available measurements, and all are null otherwise. CSV empty fields represent null; boolean uses true/false; quote RFC4180 fields and escape spreadsheet-leading =,+,-,@ in text columns with an apostrophe, marking csv_text_escaping in the manifest conditions. Numbers retain numeric sign. JSONL carries native null/bool/number; Parquet uses typed nullable int64/double/UTF8/bool columns, decimal sequences UTF8. Include gaps, branches, provenance, units and decoder/method versions. No provider secrets or opaque reasoning state.

## Defaults and change ownership

Configuration ownership follows the deployment: Docker and server installs use environment variables or `config.json`; the Windows portable shipment is configured in the native control-center Settings page. The web Settings workspace is a read-only report of effective values, sources and restart state for every deployment.

Configuration rejects duplicate IDs, invalid rule depth/node counts, nonpositive capacities, mismatched units, invalid profile target ordering and critical_min below caution_min. Null bands are allowed and mean unclassified, not zero. Reference state evaluation checks critical then caution then target/cold; equal target/caution boundary belongs to caution. data_dir/bind changes require restart; other valid changes apply atomically. Endpoint/model/protocol changes cancel the affected run and invalidate old-scope results before switching. Time Trial race-candidate evaluation returns422 unsupported_mode; lap comparisons and execution analysis remain available.

`security.origin_check` defaults true and is owned by the environment or the native Windows Settings page. `agent.compaction` defaults to enabled, an80% trigger and a25% recent tail; `agent.generation` carries optional temperature, top-p and Responses parallel-tool-call values. Prompt revisions, activity events, transcript messages and compaction summaries are append-only data, not configuration. The web Settings workspace edits agent, prompt and compaction fields; endpoint connection fields and API keys remain outside it. Invocation detail stores the exact system-prompt snapshot and model-visible input even when a prompt revision is later deleted.

[defaults.json](defaults.json) is the exact first-run configuration; model/search/voice are disabled until endpoints are configured. Timed strategy calls and continuous mode are off. After a model endpoint is enabled, lap/significant-event rules are active. UI exposes a simple cadence summary and an advanced rule editor.

Shared contract changes require updating schema, examples, both client/server bindings and affected capability specs in the same implementation patch. Do not create another shape per workspace or provider. Future implementation commands referenced in tasks are obligations to create the named package/test; they are not checks that ran during specification authoring.
